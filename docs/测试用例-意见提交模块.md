## 二、Postman 配置（照抄即可跑通）

| 配置项 | 值 |
|---|---|
| 请求方法 | `POST` |
| 请求 URL | `http://localhost:8080/submit` |
| Body 类型 | `x-www-form-urlencoded`（**不能用 JSON**） |
| 参数 1 | `username` = `张三` |
| 参数 2 | `content` = `这是一条测试内容` |

`POST /submit` 用 `@ModelAttribute Feedback` 接收，属于表单提交，不是 JSON 接口。
选 `raw → JSON` 会直接返回 500，这不是稳定的接口行为，而是一条缺陷（见 BUG-003）。

## 四、缺陷清单（4 处，均已复现）

| 编号 | 缺陷描述 | 复现步骤 | 期望 | 实际 | 严重程度 | 关联用例 |
|---|---|---|---|---|---|---|
| BUG-001 | 必填项无校验，空值与纯空格均可提交入库 | 提交 username 为空 / content 为空 / 纯空格 | 拦截并提示必填 | 302 提交成功，脏数据入库 | 一般 | TC-002、003、004、005、006 |
| BUG-002 | 提交人超长（>50 字符）直接返回 500 | 提交 username=300 字符 | 提示长度超限 | HTTP 500，暴露异常堆栈 | 严重 | TC-009 |
| BUG-003 | 参数缺失或请求格式非法时返回 500 | 不传 username；或以 JSON 提交 | 返回 4xx 或友好提示 | HTTP 500，无统一异常处理 | 严重 | TC-017、TC-018 |
| BUG-004 | 列表页无访问控制，未登录可查看全部反馈 | 无痕窗口直接访问 /list | 跳转登录页 | HTTP 200，内容全量展示 | 严重 | TC-020 |

**另外一条改进建议（不算缺陷）**

- 重复提交未做防护：快速连点会写入两条相同记录，建议前端按钮置灰 + 后端做幂等校验（TC-016）

**修复建议**

- BUG-001：在 `Feedback` 的 `username`、`content` 上加 `@NotBlank`，Controller 参数加 `@Valid`，配合 `BindingResult` 回显错误信息
- BUG-002：加 `@Size(max = 50)` 前置校验，避免依赖数据库长度约束报错
- BUG-003：加 `@ControllerAdvice` 全局异常处理器，统一返回友好错误页；缺失参数用 `@RequestParam(required = false)` + 显式判空
- BUG-004：接入 Spring Security 或添加拦截器校验会话，未登录时重定向到登录页

## 五、设计方法拆解（这 20 条是怎么来的）

### 等价类划分（以 username 为例）

| 划分 | 具体类 | 对应用例 |
|---|---|---|
| 有效等价类 | 非空、普通字符、长度正常 | TC-001、TC-007、TC-008 |
| 无效等价类 | 为空 | TC-002、TC-004、TC-018 |
| 无效等价类 | 纯空格 | TC-005 |
| 无效等价类 | 超长 | TC-009 |
| 无效等价类 | 含特殊字符 | TC-011 |

规则：每个无效等价类单独一条用例（系统要分别挡住），有效等价类可合并覆盖。

### 边界值分析

| 边界点 | 取值 | 对应用例 |
|---|---|---|
| 下边界 | 长度 1 | TC-007 |
| 下边界外 | 长度 0（空） | TC-002 |
| 上边界 | 长度 50（varchar(50)） | TC-008 |
| 上边界外 | 长度 300 | TC-009 |

> 边界值必须结合**字段真实类型**：`username` 是 `varchar(50)`，超长会报错；
> `content` 是 `text`，能存 65535 字节，5000 字符完全放得下，不会报错。
> 如果不查表结构就写预期，很容易得出"超长一定报错"的错误结论——TC-010 就是这么纠正过来的。

### 场景法

- 正常流：提交 → 列表可见（TC-001）
- 异常流：重复提交（TC-016）
- 数据流转：提交后缓存是否失效（TC-019）

### 错误推测法

非 ASCII 字符、emoji、特殊符号（TC-011、TC-012）

### 安全测试

XSS、SQL 注入、越权访问（TC-013 至 TC-015、TC-020）

> **一个重要的测试结论**：TC-013、TC-014 的 XSS 测试**没有发现问题**。
> Thymeleaf 使用 `th:text` 默认转义输出，`<script>` 在页面上显示为文本而非执行。
> 所以"输入原样入库"本身不是漏洞，**输出是否转义才是关键**。
> 这条"未发现缺陷"的结论同样要写进测试报告——测试的意义是给出真实判断，不是非得找出 bug。
